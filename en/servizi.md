One cycle in four phases, for organizations that depend on websites and web applications. The price is agreed before we start, based on the number of systems and the type of hosting.

## Prevent
Inventory of PHP versions and components in use, on every site and server. Updating PHP and applications to fixed versions. On shared or managed hosting, we check with the provider that the update was really carried out.

## Detect
We check recently modified files, PHP files in places where they should not be, unusual users and access, and suspicious requests in the logs. A check cannot guarantee that nothing happened: we state what we found and what we did not.

## Respond
Rotating passwords for the control panel, database, FTP/SSH, plus API keys and tokens on the server. If a compromise emerges, clear guidance on next steps and a written report of what was done.

## Recover
Backup set up or checked, with a restore test. A written restart procedure, so that in an incident you already know what to do.

## How an engagement works
1. **Written engagement**: we define which systems are in scope.
2. **Assessment**: versions, configuration, signs of compromise.
3. **Intervention**: agreed fixes, with the price set beforehand.
4. **Report**: what we checked, what we changed, what is left to do.

## What we do not do
We do not work on systems you do not own or have a written engagement for, and we do not promise "hacker-proof" sites: we secure you against known flaws.
